How to get around it

Android

Settings → Network & internet → Private DNS → "Private DNS provider hostname" → enter one.one.one.one (or dns.google).

Samsung: Settings → Connections → More connection settings → Private DNS.

iPhone / iPad

Install Cloudflare's free 1.1.1.1 app from the App Store, open it, and switch it on. The default "1.1.1.1" mode encrypts your DNS.

Windows 11

Settings → Network & internet → Wi-Fi (or Ethernet) → Hardware properties → DNS server assignment → Edit → Manual.

Turn on IPv4. Preferred DNS 1.1.1.1, alternate 1.0.0.1. Set DNS over HTTPS to "On (automatic template)".

Mac

Easiest: install the 1.1.1.1 app for macOS, or use the browser settings below.

Chrome / Edge / Brave

Settings → Privacy and security → Security → Use secure DNS → pick Cloudflare (1.1.1.1).

Firefox

Settings → Privacy & Security → DNS over HTTPS → Max Protection → Cloudflare.

Some of it is blocked past DNS, so changing DNS won't be enough. Use a VPN: turn on WARP in the free 1.1.1.1 app, or use Proton VPN's free plan.

FAQ

Is Discord blocked on Globe?

Check the Discord card at the top of this page. It's updated every 10 minutes from a real home Globe connection, and shows whether Discord opens normally or is blocked.

What DNS works with Discord and Reddit?

See the list above. It's updated every 10 minutes with the DNS server IPs that currently return the real Discord and Reddit addresses on Globe. Some well-known ones like 1.1.1.1 and 8.8.8.8 can get hijacked by Globe, so check the list instead of guessing.

Why won't Discord or Reddit load on Globe?

Most ISP blocks work through DNS, the system that turns names like discord.com into addresses. Globe's DNS can refuse to answer or point you to a block page. Stricter blocks cut the connection based on the site's name (SNI) or its IP address.

How do I unblock Discord or Reddit on Globe?

If it's a DNS block, switch your phone or browser to encrypted DNS such as Cloudflare (one.one.one.one) or Google (dns.google). The steps above take about a minute. If the page says it's blocked past DNS, use a VPN such as the free Cloudflare WARP app.

Is using a different DNS legal?

Yes. Choosing your own DNS provider is a normal setting built into Android, iOS, Windows and every major browser.

Bakit ayaw gumana ng Discord o Reddit sa Globe?

Kadalasan, hinaharangan ito ng Globe sa DNS. Palitan ang Private DNS ng phone mo sa one.one.one.one para gumana ulit. Kung naka-block pa rin, gumamit ng VPN gaya ng libreng Cloudflare WARP.

More info for nerds

Captured 2026-09-23 from a home Globe connection. Try these yourself (on Windows, nslookup discord.com 1.1.1.1 works in place of dig).

1. Globe's DNS answers with a block page

Globe's resolvers answer discord.com with a CNAME to its block page instead of Discord's real Cloudflare IPs.

# uses your default DNS, which on Globe is Globe's resolver
$ dig discord.com +short
forbiddenaccess.globe.com.ph.
8.232.13.4

2. Queries to 1.1.1.1 and 8.8.8.8 are hijacked

Plain DNS (UDP port 53) sent to Cloudflare, Google and OpenDNS is intercepted in transit and answered by Globe, with the same block page:

$ dig @1.1.1.1 discord.com +short
forbiddenaccess.globe.com.ph.
8.232.13.4

$ dig @8.8.8.8 discord.com +short
forbiddenaccess.globe.com.ph.
8.232.13.4

Other resolvers aren't intercepted, so they return Discord's real addresses:

$ dig @9.9.9.9 discord.com +short
162.159.136.232
162.159.138.232
162.159.135.232
…

3. Proof it's Globe answering, not Google

o-o.myaddr.l.google.com is a special name: Google's servers reply with the IP of the resolver that asked. A real Google resolver answers with a Google address (172.253.x.x), which is what you get over encrypted DNS. Over plain DNS to 8.8.8.8, it comes back with a Globe address:

# encrypted: reaches the real Google
$ curl -s 'https://dns.google/resolve?name=o-o.myaddr.l.google.com&type=TXT'
… "data":"172.253.6.18" …      ← Google

# plain: intercepted
$ dig @8.8.8.8 o-o.myaddr.l.google.com TXT +short
"2001:fd8:2f2:8::9"            ← not Google

$ whois -h whois.cymru.com " 2001:fd8:2f2:8::9"
AS    | IP                | AS Name
4775  | 2001:fd8:2f2:8::9 | GLOBE-TELECOM-AS - Globe Telecoms, PH

Same story for Cloudflare. The real 1.1.1.1 answers id.server with the datacenter you reached (like "mnl04"). On Globe, whatever answers has no idea:

$ dig @1.1.1.1 id.server TXT CH
;; ->>HEADER<<- opcode: QUERY, status: NOERROR
;; flags: qr aa rd; QUERY: 1, ANSWER: 0      ← empty, not Cloudflare

4. The block page itself

8.232.13.4 is hosted on Google Cloud, and its TLS certificate is for Globe's block page, not Discord. This is also how the probe detects block pages automatically: a real answer must present a valid certificate for the site.

$ openssl s_client -connect 8.232.13.4:443 -servername discord.com </dev/null 2>/dev/null \
    | openssl x509 -noout -subject -issuer
subject=CN=forbiddenaccess.globe.com.ph
issuer=C=US, O=Google Trust Services, CN=WR3

$ whois -h whois.cymru.com " 8.232.13.4"
396982 | 8.232.13.4 | GOOGLE-CLOUD-PLATFORM - Google LLC, US

5. Encrypted DNS and the connection itself are untouched

DNS over HTTPS/TLS isn't intercepted, and connections to Discord's real IPs complete a normal TLS handshake with SNI=discord.com. So there's no SNI or IP filtering (yet). This is a pure DNS block.

$ curl -s -H 'accept: application/dns-json' \
    'https://cloudflare-dns.com/dns-query?name=discord.com&type=A'
{"Answer":[{"name":"discord.com","type":1,"data":"162.159.138.232"}, …]}

$ curl -sI https://discord.com --resolve discord.com:443:162.159.136.232 | head -1
HTTP/2 200

How the probe decides

  • Blocked (DNS): the answer is NXDOMAIN/REFUSED/empty, a private/bogus IP, a CNAME to a known block page (like forbiddenaccess.globe.com.ph), a known block page IP, or an IP whose TLS certificate doesn't match the site.
  • No reply: the resolver didn't answer a control query (wikipedia.org), so it's down or unreachable, not blocking.
  • —: not offered by that provider, or the resolver timed out or dropped the connection on some lookups. Flaky, not proof of blocking.
  • Hijacked: a third-party resolver's plain DNS returns the ISP's own block page, or a query to an address that runs no DNS server (192.0.2.1) gets an answer.
  • Filtered by name (SNI): a TLS handshake to the site's real IP fails with the real name but succeeds with a decoy name.
  • IP blocked: the handshake fails with both names.

Every failure is retried before it counts. The probe's source is in this site's GitHub repo.

An automated probe checks every 10 minutes. It tests DNS answers from each server, whether plain DNS traffic is being hijacked, and whether connections are cut based on the site's name (SNI) or IP address.
